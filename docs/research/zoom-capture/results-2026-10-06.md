# Zoom issue #37: test results, 2026-10-06

Issue #37 remains open. This session adds live caption, speaker, layout, language
and breakout DOM evidence. The existing recorder captured remote speech before,
inside and after a breakout room in one audio file. This was a research-harness
test; the Zoom adapter, caption observer recovery and complete extension flow
remain unverified.

The separate #48 decision is complete: [README guidance only](../../../README.md#participant-notice-and-consent).

## Follow-up observations

- **U9/U10, muted participants and layout controls:** a four-person gallery kept
  Participant F's active-tile class while all four participants were muted. The
  active class alone does not prove current speech. The participant panel exposed
  each display name and `computer audio muted,video off` in its row's accessible
  label, plus an `audio-muted` SVG class. Its list uses React Virtualized, so its DOM
  must not be treated as the complete roster in a larger meeting.
- **U9, Hide Non-Video:** selecting Hide Non-Video Participants changed the menu
  action to Show Non-Video Participants. All four tiles remained visible when all
  four cameras were off. This establishes the all-video-off fallback only; a
  mixed-camera meeting and a hidden speaking participant remain untested. The
  setting was restored after the check.
- **U9, gallery ordering:** the sort submenu exposed first name and last name in
  both alphabetic directions, plus both entry-time directions. Follow host video
  order was not present in this captured menu. This does not establish whether the
  option is available in other meeting states.
- **U11, shared caption language:** Participant B selected French with translation
  off. Zoom first displayed “Captions will appear in this language for everyone.”
  Before Save, the host still showed English. After Save, both host and participant
  showed French. Saving English again restored the host's English setting.
  Language propagation is confirmed; caption accuracy and independent translated
  captions are not.
- **U8, timeout:** both host and Participant B later displayed “Joining Meeting
  Timeout or Browser restriction”, with Report Problem, Retry and Leave controls.
  The dialog does not identify the cause. The user then created a new meeting,
  where the host and Participant A were observed. That new meeting does not prove
  that Retry or reconnection recovered the earlier meeting.

## Recorder and microphone results

The temporary research extension, version `0.0.1`, used the existing bundled
recorder without changes to recorder code. The host used signed-in external Chrome
on macOS. Participant A supplied a 9.319-second synthetic speech clip through its
microphone input. Zoom generated the captions through its normal speech service:

> This is Participant A. The remote audio check is in progress. My test marker is
> Amber Bridge Nine. We will review the recording after this sentence.

The [sanitized audio and transition evidence](audio-transitions-2026-10-06.json)
contains the measured results, source filenames and selected transition states.
Audio files remain outside the repository.

The first remote-audio recording lasted 246.12 seconds and contained 3,962,230
bytes. The maximum RMS level was 0.205316 and the maximum absolute sample value
was 0.807364. Nineteen half-second sample windows exceeded the RMS threshold of
0.003. The recording stopped normally with no recorder error. Microphone capture
was off for this check.

The breakout recording lasted 1,530.42 seconds and contained 24,350,573 bytes.
It was a 48,000 Hz stereo recording. Analysis used channel 0, half-second sample
windows and the same RMS threshold. The controlled clip was played at three points:

| State | Clip start, UTC | Offset from recording start | Maximum RMS | Maximum absolute sample | Half-second windows above threshold |
|---|---|---|---|---|---|
| Main session before breakout | 09:22:06.408 | 127.288 s | 0.208575 | 0.830500 | 19 |
| Room 1 | 09:32:23.616 | 744.496 s | 0.201475 | 0.814137 | 20 |
| Main session after return | 09:43:02.412 | 1,383.292 s | 0.204831 | 0.829755 | 19 |

For each clip, the ten-second quiet windows before and after the speech check
contained no sample windows above the threshold. The three speech intervals were
present in the same recording, which stopped normally. These measurements establish
remote-audio capture at each point; they are not a speech-quality score or proof
of gap-free audio during room transitions.

The recorder logged one start and a silence event 45 seconds later, before the
first test clip. Four `tabs.onUpdated` events changed the tab's audible state during
the two room transitions. The captured events contained no URL or loading-status
change and no recorder error. Zoom required Join Audio and Show Captions actions
after room changes. Caption observer recovery was not part of this harness test.

The first local microphone attempt failed with `Permission dismissed`. At
08:45:17.250, a visible extension page obtained a microphone grant; the permission
state changed from `prompt` to `granted`. `permissions.getAll()` returned
`activeTab`, `storage`, `tabs`, `tabCapture` and `offscreen`, without `audioCapture`.
After this grant, the recorder reported a live microphone track and no microphone
error while Zoom computer audio was also joined.

That local microphone recording lasted 274.38 seconds. Its maximum RMS level was
0.000020797, and none of its 549 half-second sample windows exceeded 0.003.
The attempted local speech also produced no Zoom caption. This check confirms
concurrent audio tracks on this macOS session, but cannot establish local voice
capture or echo behaviour. It does not identify a recorder defect. Windows, Linux
and the product's fresh-profile permission flow still need tests under issue #49.
